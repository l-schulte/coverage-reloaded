## What I do

I perform a thorough integrity and sanity audit of collected LCOV coverage artifacts against Git repository source trees for a given project.

Whenever `check_lcov_sanity.py` is run for a project (`projects/<p>/lcov_sanity_report.csv`), I:
1. **Analyze aggregate run metrics** (total commits, OK, CRITICAL_ANOMALY, WARNING, ERROR, NOT_APPLICABLE).
2. **Audit structural integrity** to confirm zero ghost files (paths in LCOV that do not exist in Git) and zero artifact leaks (coverage recorded on `dist/`, `build/`, `out/`).
3. **Evaluate longitudinal coverage trends and denominator shifts** across project eras, config changes (such as Jest `collectCoverageFrom` or migrations between Jest/Mocha/Vitest/Node test runner), and non-bailing test failure states.
4. **Conduct causal root-cause attribution on flagged anomalies** (differentiating intentional project test boundaries, e.g. auto-generated icon components or e2e apps, from genuine pipeline collection defects).
5. **Generate and maintain the canonical documentation artifact: `projects/<p>/LCOV_SANITY.md`**.

## Analysis Protocol

When auditing a project:

### Step 1: Execute `check_lcov_sanity.py`
Run the sanity checker across all commits:
```bash
python3 scripts/check_lcov_sanity.py <project> --verbose
```
Wait for execution to complete and ensure `projects/<p>/lcov_sanity_report.csv` is written.

### Step 2: Extract Statistical Summaries
Execute a python inspection one-liner on `projects/<p>/lcov_sanity_report.csv`:
- Count statuses: `OK`, `CRITICAL_ANOMALY`, `WARNING`, `ERROR`, `NOT_APPLICABLE`.
- Calculate sum of `ghost_count` and `leak_count`.
- Compute coverage ratio distribution: minimum, average, maximum, and identify sudden drops (> 20%).
- Group and rank `missing_dirs` and `missing_exts`.

### Step 3: Investigate Root Causes
- If `ghost_count > 0`: inspect sample ghost paths. Are paths lacking repo-root normalization?
- If `leak_count > 0`: inspect which build directories were instrumented.
- If `missing_dirs` or `missing_exts` appear:
  - Check `projects/<p>/OVERVIEW.md` ("Suites excluded" / "Coverage collection").
  - Check `package.json` scripts and test runner configurations in Git (`git -C projects/<p>/repo show <hash>:package.json`).
  - Distinguish between:
    - **Intentional upstream exclusions:** e.g., generated icon sets (Material UI), end-to-end launch smoke tests (Spectron in Desktop), external documentation tools (`api-docs-builder`).
    - **Pipeline defects:** test suites present in `package.json` that our `install-and-run.sh` missed.
- If coverage ratio dropped across eras: identify the exact commit hash and commit message where the drop occurred. Check if `collectCoverageFrom` or runner changed.

### Step 4: Write `projects/<p>/LCOV_SANITY.md`
Synthesize the findings into `projects/<p>/LCOV_SANITY.md` following the canonical template.

### Step 5: Present Summary to User
Provide a concise Markdown summary to the user highlighting:
- Overall status & pass rate against the $\ge 90\%$ study criterion.
- Structural integrity (ghost files, leaks).
- Identified era shifts or root causes of any flagged anomalies.
