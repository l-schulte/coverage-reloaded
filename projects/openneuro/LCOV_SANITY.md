## 1. Study Verdict & Executive Assessment

- **Causal Study Verdict:** VALID WITH EXPLAINED HEURISTICS
- **Longitudinal Criterion (≥ 90%):** **PASS** (5,107 of 5,170 commits [98.8%] produced valid coverage)
- **Structural Integrity:** **VERIFIED WITH NOTED EXCEPTIONS** (178,979 ghost file instances, 0 artifact leak records)

### Executive Summary & Context
OpenNeuro is a neuroimaging data repository and sharing platform. The platform is organized as a Yarn/Node monorepo consisting of the API server (`packages/openneuro-server`), client app (`packages/openneuro-app`), and indexing services.

83.9% of commits pass all checks cleanly. Flagged commits stem from two distinct phenomena: (1) compiled artifact leaks into `packages/openneuro-app/dist/` registering as ghost files, and (2) UI Storybook packages (`packages/openneuro-components`) that lack behavioral unit test specs.

## 4. Coverage Scope & Longitudinal Denominators

*Definition of the codebase denominator and longitudinal stability of the exposure variable.*

### Codebase Composition & Test Boundaries
Primary web and API services are consistently covered. Storybook catalog modules (`openneuro-components`) and Deno CLI tooling (`cli/`) are intentionally excluded by upstream.

### Longitudinal Metrics
- **Effective Coverage Ratio (`lcov_src_count / git_src_count`):**
  - **Min:** 0.5185 (51.9%)
  - **Average:** 0.9159 (91.6%)
  - **Max:** 0.9966 (99.7%)

### Timeline & Era Evolution
1. **Pre-build Yarn Berry PnP Era:**
   - In OpenNeuro's monorepo, cross-package imports (`@openneuro/*`) require `dist/` folders to be emitted by `tsc -b` prior to test execution.
   - Because `packages/openneuro-app/dist/` is generated locally and ignored by Git, runner coverage tools (both Jest and Vitest) captured coverage on the emitted JavaScript files, bloating the LCOV with uncommitted paths.
2. **Coverage Denominator & Ratio:**
   - Despite ghost file leaks, genuine source files in Git are thoroughly covered, maintaining an average coverage ratio of **91.6%**.

## 5. Automated Checker Findings & Causal Attribution

*Detailed attribution of flags raised by `check_lcov_sanity.py` heuristics.*

| Flag / Detected Pattern | Affected Commits | Attribution Category | Root Cause & Upstream Mechanism |
|---|---|---|---|
| `GHOST_FILES` | 678 (13.1%) | Nested Build Artifact | Paths pointing to `packages/openneuro-app/dist/*.js` bypassing root-level compiled filter |
| `MISSING_DIR:packages/openneuro-components` | 416 (8.0%) | Storybook Catalog | Storybook UI component catalog without unit test specifications |
| `MISSING_DIR:cli` | 33 (0.6%) | Peripheral Tooling | Deno-based CLI tool not executed by Node/Yarn runner |

### Detailed Analysis of Findings
- **Ghost Files (`GHOST_FILES`):** 678 commits contain paths pointing to `packages/openneuro-app/dist/*.js`. Because `check_lcov_sanity.py` only checks root-level `COMPILED_DIR_PREFIXES` (e.g. `dist/`), nested `packages/*/dist/` paths bypass the artifact leak filter and are flagged as ghost files because they do not exist in the Git tree.
- **Missing Directory (`MISSING_DIR:packages/openneuro-components`):** 416 commits. `packages/openneuro-components` is a Storybook UI component catalog composed of `.stories.tsx` components and styleguides. Upstream CI never ran unit tests or coverage on this directory because no `*.spec.ts` files existed there.
- **Missing Directory (`MISSING_DIR:cli`):** 33 commits. The `cli/` directory contains the Deno-based OpenNeuro CLI, which is not tested by the Node/Yarn test runner suite.

### Causal Attribution
- **Classification:** **Monorepo Build Interaction & Component Catalog Architecture** (Upstream design / runner configuration).
- **Mechanism:**
  - Build-time emission of `packages/*/dist/` is an upstream architectural necessity for Yarn Berry PnP module resolution.
  - Test runners unconstrained by nested `!packages/*/dist/**` coverage exclusion patterns instrument both TypeScript sources and transpiled JavaScript artifacts.

## 6. Downstream Methodological Guidance

1. **Bug-Introduction & SZZ Validity:**
   - **Crucial Filtering Step:** Downstream tools must filter out all LCOV records with prefix `packages/*/dist/**` before linking coverage lines to Git blame. Because those lines represent compiled bundles, attempting to map them to Git commits will fail or produce synthetic mismatches. Genuine source lines (`packages/*/src/**`) map accurately.
2. **Storybook Components Exposure:**
   - Researchers studying bug introduction should note that `packages/openneuro-components` has 0% exposure throughout the era where it functioned as a standalone Storybook package.
3. **Action Items:**
   - In future pipeline revisions, adding `!packages/*/dist/**` to the runner coverage exclusions in `install-and-run.sh` would prevent nested compiled artifacts from entering LCOVs.

## 7. Coverage Measurement Regimes and Partial Runs (audit addendum, 2026-11-05)


This section supersedes the mechanism stated in §2 and §4.2 and records two things that
are not visible from the aggregate statistics: why the recorded line-coverage series steps
at four dates, and which runs lost test suites.

Nothing here was fixed at collection level and no commit was re-run. Compiled/generated
records are removed from LCOVs at study level, uncovered lines in excluded files are
backfilled at study level, and partial runs are kept as measured and flagged.

### 6.1 Three step changes, decomposed

Recomputed directly from the stored LCOVs (per-record `LF`/`LH`, `(empty-report)` markers
identified). "Artifact-free" excludes records under `packages/*/dist/`, `.pnp.cjs` and
`.pnp.loader.mjs`.

| Transition | Recorded | Artifact-free | What moved |
|---|---|---|---|
| `f457b4bf761c` → `6030b62eca51` | 36.48% → 75.89% | ≈69.6% → ≈64.1% | jest → vitest migration; scope change plus a generated-file leak |
| `cce4db9c6ef8` → `47b581a428c4` | 87.37% → 41.10% | 64.8% → 64.8% | 341 shared source files have **byte-identical** `LF`/`LH`; only generated/untested records changed |
| `694285090a52` → `7cf1848374de` | 47.74% → 22.14% | 47.7% → 42.7% (src only) | nested `dist/` leak plus a line-accounting change; test results identical (130 files, 416 tests, ~265 s) |

### 6.2 Four mechanisms

**R1 — nested `packages/*/dist` leak starts at `7cf1848374de` (vitest 1.6.1 → 3.2.4).**
`yarn build` (`tsc -b`) runs before the tests and emits each package's `dist/`. The two
coverage providers build their file filter differently:

- vitest 1.6.1 (`@vitest/coverage-v8`): `exclude: [...defaultExclude, ...defaultInclude, ...this.options.exclude]`
  where `defaultExclude` is the *test-file* list, which contains `**/dist/**`.
- vitest 3.2.4: `exclude: this.options.exclude`, i.e. the *coverage* defaults, whose only
  `dist` pattern is root-level `dist/**`.

Nested build output therefore becomes instrumentable only from vitest 3 onward.
Evidence: `lcov_sanity_report.csv` ghost counts are `0` up to `694285090a52`, `541` at
`7cf1848374de`, and `554` for every subsequent commit.

**R2 — `.pnp.cjs` / `.pnp.loader.mjs` leak, 2022-11 → 2024-05 only.**
`**/[.]**` was added to the coverage exclude defaults in vitest 1.x and is absent in 0.25.2
and 0.34.4. Yarn Berry loads `.pnp.cjs` in every Node process, so it is reported as fully
covered: 42,547 lines (`LH` 42,382) at `cce4db9c6ef8`, i.e. 64.8% of the denominator and
73.9% of the numerator.

**R3 — untested-file enumeration is not stable across runner versions.**
jest `collectCoverageFrom` includes untested files (277 empty reports at `f457b4bf761c`);
vitest 0.25.2 with the c8 provider reports loaded files only (0 empty reports); vitest 1.x
enumerates untested files again (217 at `47b581a428c4`, 168 at `694285090a52`).

**R4 — `ignoreEmptyLines` default `false` → `true` in vitest 3.**
At 1.6.1 `LF` equals the physical line count of each file; at 3.2.4 only statement lines are
counted (`src/scripts/app.tsx`: 43 → 31). This is why src-only coverage moves 47.7% → 42.7%
between two commits with identical test results.

### 6.4 Runs that lost test suites

A "lost suite" is a test file that failed to **load**, not a test that loaded and failed.
Detected from the runner output (jest `● Test suite failed to run`; vitest whole-file
`FAIL <path> [ <path> ]`), excluding compiled `dist/` mirrors and Deno `cli/` specs.

Census: **202 commits (3.9%)**, **665 source-spec executions**, 96 distinct spec files,
31 broken windows (17 jest, 14 vitest). 152 commits in the jest era (2021-03-05 →
2022-11-07), 50 in the vitest era.

| Executions | Family | Verdict | Evidence |
|---|---|---|---|
| 310 | module resolution (vite 133, node 109, PnP 68) | intrinsic | every failing specifier resolved against the importer at that sha resolves to nothing (734/734 target instances). `tsconfig` emits to `dist/`, never into `src/`, so no build can create the target. |
| 77 | `No test suite found` | intrinsic | 57 executions: 19 specs that `import { describe } from "vitest"` in `openneuro-components`/`openneuro-server` (see below). 20 executions: spec files with zero tests at that sha. |
| 63 | `import.meta` parse error under jest | intrinsic | `config.ts` uses `import.meta.env`; the commit's `babel.config.js` has no `import.meta` transform and the runner is jest. |
| 50 | assorted (`fetch is not defined`, `gql is not defined`, render errors) | intrinsic, not individually verified | — |
| 36 | transitive dependency crash (`Cannot read property 'get'`) | intrinsic | stack is inside `superagent-proxy@3.0.0` → `node-mailjet@3.3.5`; the sha's lockfile resolves `superagent@6.1.0` against the declared peer range `>= 0.15.4`, `1`, `2` or `3`. |
| 34 | removed dependency subpath (`jest-dom/extend-expect`) | intrinsic | lockfile pins `@testing-library/jest-dom@6.1.3`, which removed that subpath. |
| 30 | undeclared workspace package | intrinsic | the sha's workspace package is named `@openneuro/client`; source imports `openneuro-client`. |
| 25 | `require.requireMock is not a function` | intrinsic | commit pins `jest@26.6.3`; `jest-runtime@26.6.3` does not attach `requireMock` to the module-scoped `require`. |
| 13 | app config / mail credentials | intrinsic (3 of them are an upstream regression window) | 10: the commit's own `moduleNameMapper` maps `@openneuro/components/search-page` to `packages/openneuro-components/search-page/src`, which does not exist. 3: see below. |
| 12 | missing peer dependency | intrinsic, not individually verified | PnP rejects an undeclared peer at the importing package. |
| 9 | asset import not transformed (`.png`) | intrinsic | jest has no asset transform configured at those commits. |
| 6 | `must contain at least one test` | intrinsic | — |

**`No test suite found` root cause.** `vitest@0.25.2` declares `jsdom` as an optional peer
dependency, so Yarn PnP creates one copy of vitest per distinct peer resolution. At
`33379eed94` the workspaces resolve three different contexts (root/app `jsdom 16.7.0`,
`openneuro-components` none, `openneuro-server` `11.12.0`), producing three `vitest`
directories. The CLI runs from the root, so the `describe`/`it` it installs as globals come
from the root copy. A spec in another package that imports vitest gets a different module
instance: measured identity in the container, `imported describe === globalThis.describe`
was **false** in `openneuro-components` and **true** in `openneuro-app`; importing the root
copy explicitly also gave **true**. Registrations therefore land in a collector the runner
never reads, `file.tasks` stays empty, and `runFiles` sets
`No test suite found in file …`. All 19 non-empty cases are in the 2022-11-15/16 migration
window.

**Mailjet window (`e7764b5b41`, `5770bfd37c`, `6e4a7370ea`).** `e7764b5b41` replaced the
plain nodemailer transport with `nodemailer-mailjet-transport`; `node-mailjet` throws at
import time when the API key is unset, so every spec that imports the email module fails to
load. The parent `e6fae8f69e` passes, and `bf339bd320` ("fix(server): Log emails if mailjet
is not configured") wraps the construction in `try/catch`, after which the spec passes for
the rest of the history. This is an upstream regression with a 13-minute window, not a
collection defect.

### 6.5 Container verification

Three detached containers, one per mechanism cluster, each mounted on a scratch output
directory; the project's `output/` and `logs/` were not written to. At each commit the
dependency install was run through `install-and-run.sh` and interrupted before the suite, so
the spec could be re-run under the project's own command. Where the coverage leg was not
re-run, the archived run at the same sha is cited instead.

| Family | Commit | Project's own command (re-run) | Coverage invocation |
|---|---|---|---|
| `No test suite found` | `33379eed94` | fails | fails in the archived run at the same sha (c8 provider) |
| undeclared workspace package | `45d4c158ed` | fails | fails (re-run in container) |
| transitive dependency crash | `e7764b5b41` | fails | not run — the failure is at import, before instrumentation |
| mail credentials | `e7764b5b41` | fails, then **passes 3/3** with `CRN_SERVER_MAIL_API_KEY` / `_API_SECRET` / `_FROM` from the repo's own `config.env.example` | fails in the archived run at the same sha |

**Conclusion: 0 of the 665 lost executions are attributable to the collection pipeline.**
A re-run cannot materialise a file that does not exist at the sha, restore a renamed
workspace package, relax a peer range recorded in the commit's own lockfile, or merge two
vitest module instances.

### 6.6 Known collector defects (recorded, not fixed)

1. `assert_suite_ran` only checks that at least one test ran. A run in which 128 of 255 test
   files load passes the same check as a complete run, so partial runs are indistinguishable
   from complete ones at artefact level.
2. The `[WARN] yarn build (tsc -b) reported type errors` message also fires when the commit
   has no `build` script at all (verified at `5b322b4a74`), because a missing script also
   exits non-zero. The message names tsc regardless of whether tsc ran.
3. In the vitest era, compiled spec copies under `packages/*/dist/**/__tests__/` are also
   collected as test files, because the project's `test.exclude` entry `**/dist` does not
   match files *below* `dist/`. At `cce4db9c6ef8` and `47b581a428c4` this yields 255
   collected files, of which 127 are such mirrors and all fail to load. Coverage is
   unaffected (the source specs pass), but the exit code is 1. Only one commit is affected
   in its pass/fail label; the rest also carry genuine test failures.

### 6.7 Consequence for the exposure variable

- 88 of the 202 commits (65 jest, 23 vitest) report **zero failing tests**: they are recorded
  as test failures only because suites did not load. They remain usable coverage but are
  partial.
- Because the losses are intrinsic to each commit, the partial coverage is a faithful
  measurement of that commit, not a pipeline error. It should be flagged as
  `partial_by_commit` where the study needs complete denominators.
- Files that are only reachable from a lost suite drop to 0%, which the file-level filter in
  §5 cannot repair. The affected commit list is reproducible from the stored logs with the
  predicates above (`Test suite failed to run`, whole-file `FAIL … [ … ]`), excluding
  `dist/` mirrors and `cli/` specs.
